# TrainSolve 客户端 · 公开版（不含任何账号与密钥）

本包**只有程序**：目录里带 `portable.txt`，`config.toml` 的账号、密码、API Key **全是空的**，
不含任何凭据。第一次打开时按下面填自己的学号/密码和 Key 即可。

## 第一次使用（3 步）

1. 双击 `TrainSolveClient.exe`（单文件内置 Playwright，首次启动要解压，约 4–5 秒，属正常）；
2. 顶部填 **平台地址 / 学号 / 密码**（默认已填训练平台地址）；
3. 点右上 **更换模型…**，填你自己的：
   - **API Key**（DeepSeek 官方 `sk-` 开头，或任何 OpenAI 兼容网关的 Key）
   - **接口地址**（官方填 `https://api.deepseek.com`；自建网关填 `http://你的地址/v1`）
   - **模型名**（官方 `deepseek-flash` 或 `deepseek-v4-pro`；自建网关按它的模型 id 填）
   - 点 **测试当前填写** 确认能连通 → **保存并应用**（0.6.9 起推理型模型只回了思维链、
     正文被预算截断也算可用；保存后配置会加密写成 `config.toml.enc`，见下文「配置保存在哪」）

填完点 **登录**，然后左侧选难度/标签 → **开始自动刷题** / **全自动（连续刷）**。

> **装好默认是「试运行」**：包内 `config.toml` 预置的是 `dry_run = true`、`submit = false`，
> 也就是说**只解题、不往平台提交**。确认题目、代码和日志都符合预期后，再自己打开真提交。
>
> 0.6.9 起界面一保存就会把配置**加密**写成 `config.toml.enc` 并删掉明文，所以开真提交分两种情况：
>
> 1. **还没在界面保存过**（同目录仍是明文 `config.toml`）：用记事本打开它，把
>    `dry_run = true` 改成 `false`、`submit = false` 改成 `true`，再启动客户端；
> 2. **已经加密成 `config.toml.enc`**：用源码 / 命令行版的 `trainsolve decrypt-config` 解出明文，
>    改完再 `trainsolve encrypt-config --remove-plaintext` 重新加密；没有 Python 环境就删掉
>    `config.toml.enc`，照 `config.example.toml` 重建一份明文再启动（账号与 Key 要重填）。
>
> GUI 里**没有**这两个开关，只能改配置文件。**每次真提交都会消耗平台上有限的作答/提交机会**，
> 正式开跑前建议先手动做一题确认流程。`confirm = true` 的提交确认弹窗默认开着，别关。

## 界面速览

| 区域 | 作用 |
|---|---|
| 顶部第 1 行 | 平台地址、学号、密码、登录、设置 |
| 顶部第 2 行 | 当前模型、**更换模型…**、测一测 |
| 左侧「选题」 | 题型（默认「只做普通编程题（5）」）/ 难度 / 标签 / 数量 / 判题方式；开始自动刷题、全自动（连续刷）、抽新题（新建会话）、停止 |
| 左侧「人工模式」 | 本地自检我的代码、提交我的代码（把编辑器内容当答案交） |
| 左侧「模拟真人打字」 | 勾选后作答改在浏览器里逐字符输入 + 真实点提交（速度在设置里调） |
| 右侧页签 | 日志 · 题目 · 代码 · 评分 |

## 它做什么

```
读题干 → 写代码 → 用题面样例自测（本地 gcc 逐字节比对）
      → 不过就按 diff 改（最多 3 轮）
      → 提交 → 等评分
      → 没满分时：**自 0.5.5 起默认不再自动重答**（重答会撤销刚才的提交、清空成绩）
```

全自动模式每做完一题自动抽下一题；停止条件：题库抽空 / 本周限额 / 连续 3 题未满分 / 连续 5 次跳过 / 手动停止。

**关于“未满分自动修复”（0.5.5 起默认关闭）**：以前它会自动把失败用例回灌给模型、重答再提交；
但平台的“重答”会把已提交的记录重新打开、**清空刚才的成绩**，等于撤销提交。
现在默认关；要开就把配置里的 `auto_fix_from_judge` 改成 `true`（GUI 没有开关）。
开启后日志会两次警告：「自动重答已开启…等于撤销刚才的提交」与「本次重答会撤销刚才的提交…成绩将被清空」。

**提交留痕（0.5.5 起）**：每次提交都会在 `out\<会话ID>\` 留下 `submit_N.json`（平台原始返回 + 业务码）
和提交前后的 `record_before_submit_N.json` / `score_before_submit_N.json`。
若业务码说成功、记录却回到「未完成」，日志会明确写 **「提交状态未知：…提交被撤销」**，
不会假装“已完成”。真遇到这行，按提示重试或改用人工提交。

## 可选：本地 gcc

装了 gcc（MSYS2 / TDM-GCC 等，需在 PATH 或设置里填路径）就能在提交前做精确的样例比对；
没装也能用，只是校验弱一些，靠平台判分反馈来修。

## 配置保存在哪

本包是**便携版**（目录里有 `portable.txt`），配置只用 exe 同目录这一个位置。0.6.9 起默认加密：

- 界面保存后写的是 **`config.toml.enc`**（Windows DPAPI，只有当前 Windows 用户能解），
  同目录的明文 `config.toml` 随即被删掉；明文与加密同时存在时**只读 `.enc`**；
- 不会读取 `%APPDATA%`，也不会读取任何"别人的"配置，首次打开一定是空白的；
- `.enc` **绑定当前 Windows 用户和这台机器**：换机器、换 Windows 用户、拷给别人都解不开。
  要迁移先在原机用 `trainsolve decrypt-config` 导出明文（用完记得删），或在新机器直接重填；
- 想回到明文：删掉 `config.toml.enc`，程序没有配置时用默认值启动，重填后保存又会加密；
- 想清空重来：删掉同目录的 `config.toml.enc`（以及可能残留的 `config.toml`）再打开即可；
- 整个文件夹可以随意拷贝/改名，但加密配置只在**同一台机器的同一个 Windows 用户**下能用。

## 启动时自动清理残留（默认开）

每次打开客户端并登录后，会自动清理两类残留：

- 平台上**已过期**（答题时间已用完）的「未完成」记录——这些不会再计分，但一直占着列表；
- 本机 `%TEMP%` 里 2 小时前遗留的 `_MEI*` 解压目录（单文件 exe 被强杀时会留下，每个约 100 MB）。

**正在做的题不会被动**。想连未过期的也清，在 **设置 → 启动时自动清理残留** 里勾第二项（慎用）；
不想让它清，就取消第一个勾选。日志里出现 `🧹 启动清理：清理过期会话 N 条` 就是执行过了。

## 可选：模拟人类逐字符打字（已内置）

本包已内置「模拟真人打字」：左侧勾选 **「🧑‍💻 模拟真人打字提交」**，作答就会改成
在浏览器里逐字符敲代码 + 真实点击「提交」（Playwright driver 已打包进 exe，不用另装）。

- 工具会自动拉起一个独立配置目录的 Chrome（调试端口 9333），**不影响你日常用的浏览器**；
  第一次要在这个 Chrome 窗口里登录一次平台，之后复用登录态；
- **每次作答速度随机**（默认基准 ±25%，行内还会浮动，日志打印「🎲 本轮打字速度 ≈ …」）；
  基准速度 / 随机区间 / 错字率 / 端口 / 「只打字不提交」在 **设置** 里调；
- **每题可加一段随机「思考时间」**：设置里「每题随机思考 ×–× 分钟」（0–60，填 0 不等待），
  每道题开始作答前独立取一个值，日志会打印实际等待时长；等待期间点 **停止** 会立刻中断且不提交；
- **速度与思考区间在主界面也有一份**（0.6.5 起）：左侧「模拟真人打字」下面两行
  「打字速度 [220] 字符/分」「随机思考 [min]–[max] 分钟」，随时可改，越界自动夹紧、写反自动交换，
  与设置里那两个参数双向同步；开始跑时按主界面当前值生效；
- **答题不需要浏览器在前台**（0.6.5 起）：逐字输入走 CDP 注入，Chrome 最小化或你切去别的窗口都照常；
  每 8 行自动检查一次焦点，**先只做页面内聚焦（不动光标）**，必要时才点一下鼠标并把光标送回文末
  （0.6.7 修：以前点完光标会留在正文中间，后面的字就打错位置了）。0.6.9 起打字过程中每 12 个按键
  再确认一次焦点，连续几下都打不进编辑器就重新聚焦。锁屏不行——渲染会被节流；
- **中文注释/字符串也能打**（0.6.7 起）：ASCII 字符走真实按键（含 Shift 组合），非 ASCII 单字符走
  `Input.insertText`（等价输入法上屏，一次仍只插 1 个字符，不碰平台「>50 字符才算粘贴」的阈值）；
- **逐字符自适应**（0.6.8 起，0.6.9 加固）：每敲一个字符前先读**光标前/后**——光标前是正确前缀就
  补下一个字符，编辑器自动补的 `)` 等尾巴用 `Delete` 删掉，丢键与多插在下一次按键前吸收；
- **行首缩进不再逐格对齐**（0.6.9 起）：编辑器会「智能缩进」（回车补 8 空格、打 `{` 时整行重排并补 `}`），
  硬对齐只会和它拉锯、把刚打的字删光。C 代码的缩进不影响编译与判分，所以打字校验、暂存同步、运行核对
  统一按「忽略行首空白」比较；
- **点「停止」立刻停手**（0.6.5 起）：正在逐字打字时每敲一个字符查一次停止标志，命中即停、绝不提交，
  本题标为「已停止（打字过程中被中断，未提交）」；0.6.6 起解题算完、准备暂存/提交前、等待评分、重答前也都会查，
  点停止后**不会再暂存答案、不会再 submit**；唯一要等的是已经发出去的那次模型请求，它返回后立刻停；
- **打字时会随机退格**：设置里「随机退格 概率 / 每次最多删 × 字符」（默认 0.01 / 2），
  删掉刚打的几个字符再原样补回，内容不会变；填 0 关闭；
- 只覆盖编程题（C 语言）；打字是真实节奏，50 行大概 1.5–3 分钟。

## 照着勾了却没提交 / 一直跳过？

主界面「模拟真人打字提交」下面那行会直说当前状态：

- **试运行（dry_run=true）**：只解题、把题目和答案存到 `out\`，**不会提交**（公开包默认）；
- **不提交（submit=false）**：同上；
- **真提交**：才会消耗作答机会。

要真提交：关掉客户端，按上面「装好默认是试运行」里的两种办法改 `dry_run` / `submit` 后再打开
（0.6.9 起配置默认加密成 `config.toml.enc`，明文那份在保存后就被删了）。

开着「模拟真人打字」时，**试运行/不提交也会真的逐字打字、也会走随机思考时间**，只是最后不点提交——
所以看着像「跑得很慢」是正常的；不想等就把「模拟真人打字」取消，或把思考时间填 0。

> 客户端会在登录、换模型、保存设置时**重写配置文件**（0.6.9 起默认是加密的 `config.toml.enc`；
> 值都保留，注释会被去掉，日志里会写「已覆盖配置文件 …B → …B」）。

**指定了标签却一直「跳过」**：那个标签里的题不在你选的「题型」范围内（例如标签里全是改错题，而默认题型是「只做普通编程题（5）」）。
日志会点名是哪几种题型被排除了；客户端在连续两次跳过后会自己停下，免得白烧抽题配额与限流等待。
要做实验/复杂编程（6/7）就在命令行写 `--qtypes 5,6,7`，或在界面把「题型」改成「不限制（含实验/复杂编程、改错题、程序填空）」；也可以换个标签。

## 什么时候不会自动提交
**自检未通过**（编译不过 / 样例输出对不上）的答案默认**不提交**，避免白占一次作答机会；
确实要交就在设置里勾「自检未通过也提交（--force，不推荐）」。

## 本版变化（0.6.10）

- **默认题型收敛为普通编程题（qType 5）**：`qtypes` 默认从 `[5,6,7]` 改成 `[5]`，实验编程（6）、
  复杂编程（7）不再进默认池；界面「题型」下拉只剩「只做普通编程题（5，默认）」与
  「不限制（含实验/复杂编程、改错题、程序填空）」；`config.public.toml` / `config.example.toml` 都是
  `qtypes = [5]`。要做 6/7 用 `--qtypes 5,6,7`，或界面选「不限制」。
- 0.6.9 的内容仍在本版：配置文件 DPAPI 加密（`config.toml.enc`，`encrypt-config` / `decrypt-config`）、
  打字与暂存同步忽略行首缩进、模型自检按「正文或思维链非空」判定、CLI 开关不再覆盖配置文件。
- 0.6.8 的内容仍在本版：逐字符自适应、旧值稳定回读防重复输入、随机退格删完立即补回。

## 已知缺口（0.6.10 未解决，请先看这一节）

| 缺口 | 现象 | 现在怎么办 |
|---|---|---|
| **配置文件加密绑定本机** | `.enc` 用 Windows DPAPI，绑定当前 Windows 用户与这台机器：换机器、换用户、拷给别人都解不开；打包版没有命令行，加密后改 `dry_run` / `submit` 要按「配置保存在哪」里的办法重建明文 | 要迁移先在原机 `decrypt-config` 导出明文；只是自己换电脑就重填一遍 |
| **高 DPI 只实测了 150% 一档** | 自 0.5.1 起程序声明了 Per-Monitor V2 DPI 感知，150% 缩放下文字清晰、间距随缩放一起放大；但本机只有一块 150% 屏，**100% / 125% / 175% 未实测**，多显示器不同缩放跨屏拖动也未验 | 单屏直接用即可，**不要**再去设右键属性里的「替代高 DPI 缩放行为」，对已声明感知的程序那样做会二次缩放、反而更糊 |
| **发布包内没有版本历史** | 源码仓库已开源（`github.com/Huang0907/train-solver`，MIT），但发布 zip 里不含 `.git`；包内能标出版本的只有包名和窗口标题里的 `v0.6.10` | 需要历史与回滚请用源码仓库；只升级客户端就替换整个文件夹 |
| **随机题可能抽到白名单外的题型** | 题型选「随机（-1）」时，平台可能返回不在所选 `qtypes` 里的题型；客户端会自动跳过该题（`skip-this`），**代价是一次抽题配额 + 约 60 秒限流等待**，日志里会看到跳过原因 | 想要稳就选具体题型，不要用「随机」；随机只在“题库抽空/限额”这类场景省事 |
| 右下角进度条是视觉瑕疵 | 进度条空槽与背景同色，空闲时只剩一小块绿条，容易被误认为异常 | 不影响功能，任务运行时会滚动；留到下个版本修 |
| **真提交链路：0.5.4 出过事，0.5.5 已修，2026-11-08 复测通过** | 0.5.0 有历史真提交证据；**0.5.4 在真平台实测过一次，暴露的问题是：提交被判 0/12 后自动重答，平台把记录重新打开，刚才的成绩被撤销**；0.5.5 已修复（默认关闭自动重答、记录状态优先于业务码），**2026-11-08 已在真平台复测通过：submit 只发一次、记录停在 `state=1` / 12/12、未报「提交状态未知」**（session `fec9ac14…`，消耗一次真实提交机会）；**2026-11-11 0.6.9 真机全流程复测通过：Q3077 逐字输入 1178 字符 / 54 行、暂存 790 字符回执 `code=0`、提交 12/12，history 74→75 唯一新增本次会话** | 第一次用先在设置里保持「试运行 / 不提交」跑一轮，看清题目、答案与日志再开真提交；**别把第一次真提交留到赶作业的那个晚上** |

窗口最小尺寸按 DPI 自动计算（100% 下 980×680 逻辑像素；150% 下约 1481×1049 物理像素），
再小控件会被裁切（程序已按内容设好下限）。
